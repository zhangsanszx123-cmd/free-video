## 2. 当前项目已有能力

- [需求文档](./requirements.md) 已把无字幕视频处理列为 B1；[设计文档](./design.md) 建议通过下载音频、ASR 转写、输出统一字幕条目扩展。
- [下载适配层](../backend/app/downloader.py) 已能列出平台字幕和平台自动字幕、选择语言并转成 SRT。当前选择规则先区分人工/非自动轨道和自动轨道，再在各组内按中文、英文等顺序挑选；不是跨所有轨道一律优先中文。
- [文字稿接口](../backend/app/main.py) 的 `/api/transcript` 是同步请求：下载字幕、解析并返回纯文本和带时间戳文本；没有 ASR 回退。它直接调用下载适配层，并未复用 [任务层](../backend/app/tasks.py) 的 `fetch_transcript`。
- [结果卡片](../frontend/src/components/ResultCard.vue) 已有视频文案、复制、时间戳切换和 SRT 下载。有字幕时自动加载文字稿；没有字幕时不发起转写。请求失败统一显示“暂未识别”，没有区分无字幕与网络失败。
- [抖音适配层](../backend/app/douyin.py) 当前固定返回空字幕列表；这表示本项目没有提取抖音字幕轨道，不能据此断言所有抖音视频都没有字幕。
- [任务队列](../backend/app/jobs.py) 已支持异步处理、状态轮询和临时文件清理；可作为长音频转写的基础。[AI 模块](../backend/app/ai.py) 当前调用文本聊天接口做总结和翻译，没有音频识别实现。
- 现有测试覆盖字幕文字稿成功和无字幕报错、字幕选择、抖音字幕拒绝等行为；新增回退后需调整对应断言。

结论：已有字幕提取与展示基础，核心缺口是无可用字幕时的语音转写，以及贯通前后端的任务状态、来源标记和错误处理。

## 4. 从公开资料能确定的实现路径

### 路径 A：读取现成的文本字幕

读取平台暴露的字幕轨道，包括作者上传字幕与平台自动字幕，清洗后得到文字稿及时间轴。2outube 明确使用此路径，本项目也已具备这类能力。其边界是字幕是否存在、是否可访问、语言是否合适以及原字幕质量。

### 路径 B：从声音生成字幕

获取音频 → 语音识别（ASR）→ 带起止时间的文字片段 → 纯文本/SRT。DownSub 和 TurboScribe 的官方说明能支持这一处理模式；TurboScribe 明确使用 Whisper，不能据此推断其他竞品使用相同模型。

本项目可复用音频下载和任务队列。具体采用本机模型还是云 API，仍需结合部署机器、中文效果、预算和音频上传要求评估，本轮不锁定服务商。

### 路径 C：识别烧录在画面里的字幕

字幕成为视频像素时，无法按文本字幕轨道直接下载，需要画面文字识别（OCR）及跨帧去重、时间轴对齐。DownSub 将其作为独立工具，并要求标记字幕区域。此能力与“听声音转文字”存在不同的工程范围。

特别需要区分：画面能看到字幕，不等于平台提供可下载字幕。画面字幕也可能与实际口播不同，必须先确认用户希望保留哪一种内容。

## 5. 适合当前项目的方向建议（核心路径已确认，其余建议待确认）

建议用户路径：粘贴视频链接 → 检查可用字幕 → 有合适轨道则提取 → 无可用轨道则转写音频 → 在现有视频文案卡片展示 → 复制或导出 TXT/SRT。

建议借鉴：

1. **统一结果入口**：沿用 AnyToCopy 式结果卡片，减少重复粘贴、重新上传视频的操作。
2. **标记文字来源**：显示“平台字幕 / 平台自动字幕 / 语音转写”，帮助用户判断文字从哪里来。
3. **后台任务状态**：显示检查字幕、获取音频、排队、转写、完成；没有真实进度时使用阶段提示，不编造百分比或完成时间。
4. **可恢复的失败提示**：区分无字幕、字幕访问失败、音频获取失败、无音轨/无人声、转写服务未配置等情况，并提供适用的重试操作。
5. **统一文字与字幕产物**：正文和 SRT 来自同一份带时间的识别结果；后续总结、翻译可复用，减少重复转写。

字幕接口访问失败不等于视频没有字幕。是否直接转 ASR、是否提示后由用户触发，需要在方案中明确，尤其在云服务产生费用时。现有前端默认选第一条字幕，而后端默认按优先级选择，后续也应统一规则。

本轮不把账号、支付、持久化历史、说话人区分、全文编辑、批量转写或本地文件上传自动纳入开发范围。

## 8. 本机模型与云端服务选型对比

补充日期：2026-11-08。用户已要求先做选型对比，尚未选定部署方式或服务商。以下是官方资料核对与工程判断，没有安装模型、上传音频、调用收费接口或进行同音频效果测试。

### 8.1 部署方式的区别

这里的“本机”指运行后端的机器。网站部署到服务器后，模型也在服务器运行，不会自动借用访问者电脑或手机的显卡。

| 维度 | 本机 CPU | 本机 NVIDIA GPU | 云端识别 API |
|---|---|---|---|
| 使用费用 | 无逐分钟 API 费；占用 CPU、内存和电力 | 无逐分钟 API 费；承担显卡购置或租赁费用 | 按识别用量计费，另考虑文件存储、传输和重试成本 |
| 部署条件 | 下载模型，安装推理依赖 | 另需匹配驱动、CUDA/cuDNN 与推理库 | 开通账号和识别权限，配置 Key，解决音频传输 |
| 速度 | 受模型、CPU、线程和并发影响 | 可提升推理吞吐，但不能脱离具体配置承诺耗时 | 总耗时包括获取音频、上传/云端下载、排队及识别 |
| 中文效果 | 取决于所选模型及素材 | 与模型和解码配置相关，GPU 本身不保证更准确 | 取决于具体服务，不能直接判定一定好于本机 |
| 时间戳/SRT | 选支持时间戳的模型，统一转换为 SRT | 同左 | 选择返回分句起止时间的接口，转换为 SRT |
| 音频流向 | ASR 阶段可留在部署机器，平台视频下载仍需联网 | 同左 | 音频传到服务商；本地文件清理不能等同于服务商删除 |
| 并发维护 | 避免识别占满 CPU、影响现有下载 | 控制显存占用和识别并发 | 处理配额、限流、超时和计费；后端仍需要任务队列 |
| 更合适的场景（工程判断） | 个人少量使用，愿意等待 | 已有合适显卡、用量较多或音频需留在本机 | 普通服务器、少量至中等用量、希望先验证完整流程 |

### 8.2 具体候选

**A. 本机 faster-whisper：多语言优先候选。** Python 可直接调用，支持 CPU INT8、GPU 推理及分段/词时间戳，可将输出转换成现有字幕条目。建议用 small 多语言模型试 CPU 路径，再评估 large-v3 等 GPU 路径。模型准备完成后可从本地加载，避免运行时下载。

官方基准使用一段 13 分钟音频：i7-12700K、8 线程、small INT8 用时 1 分 42 秒、内存约 1.48GB；RTX 3070 Ti 8GB、large-v2 INT8 用时 59 秒、显存约 2.93GB。两组模型不同，不能据此单独归因 CPU/GPU 性能，也不能把耗时或中文效果套到本项目。开发预算可先预留 16GB 系统内存；GPU 路径以已有 8GB NVIDIA 显卡作为评估起点，这是规划建议而非最低配置。

来源：[faster-whisper 官方仓库及基准](https://github.com/SYSTRAN/faster-whisper)。

**B. 本机 FunASR + Paraformer-zh：中文/中英内容候选。** 官方列出该模型支持中文、英文及时间戳，可组合 VAD 和标点模块。其多模块依赖和断句需要验证，不能把不同模型如 SenseVoice 的能力直接混用。它与云端 paraformer-v2 不是可保证完全一致的部署品；本轮没有得到与其他候选同条件的准确率或耗时结果。

来源：[FunASR 官方模型列表和调用说明](https://github.com/modelscope/FunASR)。

**C. 阿里云百炼 Paraformer-v2：低识别单价候选。** 录音文件识别走任务提交与查询；官方结果示例有句子和词的毫秒起止时间，适配 SRT 的依据明确。采用文件 URL 入口时，音频必须能被服务商获取；不能将本地磁盘路径或 localhost 地址直接提交。若下载平台的源音频地址不稳定、受 IP 或请求头限制，应上传到临时对象存储后再识别。SDK 的本地文件便利入口是否适用于所选模型、是否隐含临时上传，需要实施前验证，不能视为完全无上传环节。

来源：[Paraformer Python SDK 与返回结果](https://help.aliyun.com/zh/model-studio/paraformer-recorded-speech-recognition-python-sdk)、[文件识别指南](https://help.aliyun.com/zh/model-studio/non-realtime-speech-recognition-user-guide)。

**D. 阿里云 Qwen3-ASR-Flash-Filetrans：另一云端比较候选。** 官方说明该长音频接口支持最长 12 小时，使用公网音频 URL，异步任务结束后返回结果。价格高于上述 Paraformer。当前所阅示例未充分核实用于本项目 SRT 的精确时间戳结构，因此不能只因模型较新就作为首选；需要先验证分句时间数据及中文实测收益。此处比较的是指定模型 ID，不泛指所有千问音频模型。

来源：[Qwen3 文件识别说明](https://help.aliyun.com/zh/model-studio/recording-file-recognition-qwen)。

**E. 火山引擎大模型录音文件识别极速版：避免自建文件 URL 的云端候选。** 官方接口文档允许 URL 或 Base64 音频数据二选一，并返回分句起止时间；支持不超过 2 小时、100MB 的文件，直接传数据建议尽量在 20MB 内。适合先测试短视频转写，不需要为这种调用方式额外提供公网音频地址；长文件要评估压缩、分片与时间轴拼接或其他接口。搜索索引中的新版页面只列 URL，与完整 API 页存在描述差异，因此正式采用前仍需用账号验证直接传数据能力。

来源：[极速版 API 参数、限制与结果示例](https://docs.volcengine.com/docs/doubao-voice/large-model-recording-file-lite-recognition-api?lang=en)。

### 8.3 识别费用估算

按 2026-11-08 核对的公开按量单价估算。阿里云采用华北2（北京）价格；不扣免费额度，不含折扣、对象存储、流量、下载服务器、额外模型功能及重复调用费用。单位为人民币。

| 候选 | 单价依据 | 每音频小时 | 10 分钟 | 100 小时 | 1,000 小时 |
|---|---|---:|---:|---:|---:|
| 本机模型 | 无逐分钟 API 调用费 | 算力成本另算 | — | — | — |
| Paraformer-v2 | 0.00008 元/秒 | 0.288 元 | 0.048 元 | 28.8 元 | 288 元 |
| Qwen3-ASR-Flash-Filetrans | 0.00022 元/秒 | 0.792 元 | 0.132 元 | 79.2 元 | 792 元 |
| 火山大模型录音极速版 | 4.5 元/小时 | 4.5 元 | 0.75 元 | 450 元 | 4,500 元 |

计算示例：0.00008 × 3,600 = 0.288 元/小时。实际账单按具体服务的时长口径、声道和计费粒度结算。Paraformer 价格表列出每月 10 小时免费额度，账号是否适用需在控制台确认，预算不依赖赠送额度。火山单价来自官方计费页的搜索索引，页面正文受 JavaScript 加载限制，开通前需再次在控制台核价。

来源：[百炼价格表](https://help.aliyun.com/zh/model-studio/model-pricing)、[火山计费说明](https://docs.volcengine.com/docs/doubao-voice/billing-instructions?lang=zh)。

本项目只有无可用字幕时才需要 ASR。可按“总视频小时 × 无可用字幕占比 × 单价”估算识别支出。例如每月处理 100 小时视频，其中 30% 需要 ASR，Paraformer 原价估算为 8.64 元，Qwen3 为 23.76 元；这是情景计算，不是对实际使用量的预测。

### 8.4 对当前项目的建议与实施边界

用户已确认服务器部署、多人使用，并接受云端识别与按量费用。月处理量及具体服务商尚未确定；以下保留选型依据，当前进入[云端方案设计](./video-to-text-plan.md)，不再要求重复确认音频上传意愿：

- **普通服务器、接受云处理**：优先比较 Paraformer-v2 与火山极速版。前者识别单价低、字幕时间数据明确；后者有直接传音频的数据入口，短视频验证可能更省文件托管工作。最终选择同时取决于音频传输和实测质量。
- **个人本机使用、希望音频留在本机**：优先试 faster-whisper；若主要是中文/中英内容，再与 FunASR Paraformer-zh 做同素材比较。GPU 是否值得使用应看现有硬件，无需仅为尚未验证的功能先购显卡。
- **不要首期同时实现所有后端**：先选定一种完成字幕优先、无字幕回退、时间轴和错误提示的完整流程；保留可替换接口即可。不能把支持多家适配误当成本期必需范围。

设计时需让文字稿展示、字幕导出及可能的总结/翻译共享结果，避免每次操作重新识别。现有任务过期清理不应在云端仍排队时删除源音频；云端转写也应有独立超时、限流和失败重试策略。本机路径建议先限制为单个识别任务，测量后再提高并发。

### 8.5 尚需实测的项目

选型后使用同一组音频比较：普通话清晰口播、中英混合、噪声/背景音乐、静音或纯音乐、长视频。覆盖短视频与 20–60 分钟素材。记录中文字符错误率、专有名词和数字错误、句子遗漏/重复、字幕时间偏移，以及下载、上传、排队和识别各阶段耗时；不能仅比较营销准确率或单次总时间。

已确认服务器多人使用、允许云端处理和按量费用。实测前仍需确定服务商、测试预算及样本；月处理量可在试用后观测。当前仅完成调研与方案草案，尚未开通服务或调用收费接口。

### 8.6 多人服务的设计关注点（待方案确认）

- 下载与识别分别限制并发，设置排队上限和单次音频时长上限，防止长任务占满资源。
- 对同一用户的重复请求复用处理中任务或短期结果，避免重复识别和重复计费；跨用户共享结果需另行明确访问边界。
- 云端方案需设置用量统计、预算告警及达到预算后的处理规则，具体阈值待确认。
- 任务结果与临时音频应有访问控制，不能把随机任务 ID 本身当成完整授权机制。
- 多人使用不等于必须多实例部署。首期是否继续单进程，以及是否需要重启后恢复任务，应在详细方案中确认；不自动引入数据库、Redis 或账号系统。
