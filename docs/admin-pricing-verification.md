# 后台会员价格管理：方案与验证

日期：2026-11-17。用户确认：超级管理员修改、普通管理员查看、保存确认、审计、版本保护、前台同步及付款复核。开发和自动化验证完成，待人工验收。

## 行为与边界

- `/admin/pricing` 以元修改月卡/年卡售价，范围 0.01–999999.99、最多两位小数；下一步展示原价和新价，确认后才保存。不修改免费套餐、期限或额度。
- 并发同版本仅一份修改成功，冲突刷新重确认。同值不产生新版本；审计失败回滚。
- 前台可见定价页 30 秒轮询，聚焦、变为可见或打开付款弹窗前刷新；离页停止同步。已有支付弹窗报价保持，付款提交时用服务器当前价格与版本校验。
- 套餐价格或版本变化不下单、不跳转，先展示最新金额与额度说明，等待用户再次点击。旧订单按原金额和有效期处理；价格管理本身不修改额度，额度管理的五项额度按用户后续确认对已有用户立即生效，见 [额度管理记录](./admin-limits-verification.md)。未增加审计列表页面。

## 复跑

```powershell
$env:MYSQL_TEST_DATABASE='freevideo_pricing_test'
.venv/Scripts/python -m pytest tests/test_admin.py tests/test_payments.py -q
```

新浏览器脚本在仓库根目录执行 `python -P frontend/tests/admin_pricing_ui.py`，访问 :8000 已构建页面，全部 API 模拟。既有 admin_ui.py / ui_regression.py 使用 Vite :5178。

## 人工验收

1. 超级管理员登录后台「会员价格」，检查月卡 19.90 元、年卡 99.00 元。
2. 如需实际改价，填写预期金额，经确认页保存。另一个前台定价页应在 30 秒内更新，切回页面或打开付款弹窗也刷新。
3. 两个后台标签页同时编辑同一套餐，先保存一处，再保存另一处，后一处应提示冲突，不能覆盖。
4. 普通管理员可查看价格，不能看到修改按钮。
5. 支付弹窗打开后在后台改价，再点付款，应先显示更新提示和新金额，不跳转；实际付款仅在你确认后操作。

真实改价会影响新订单。本次没有在业务库自动来回调价，也没有创建新的后台账号。
