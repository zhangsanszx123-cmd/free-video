# 套餐额度管理：设计与验收

日期：2026-11-17。用户确认五项额度对已有用户立即生效，并要求单独设计 UI。本轮实现、测试和文档按用户要求一并纳入 Git，提交不代表人工验收通过。

## 页面与规则

- 独立 `/admin/limits`，保留 `/admin/pricing` 价格管理。普通管理员只读、超级管理员可修改。
- 桌面左列为功能及计量方式，右侧三档套餐逐行对照；月卡浅靛蓝，年卡图标金色，与既有后台保持一致。手机使用三个套餐按钮切换单列详情，不压缩为横向宽表。
- 每次编辑一档五项额度，标明当前值、单位、范围，输入整数；确认页只显示变更项，调低额度用琥珀色提示，并明确立即影响已有用户。
- 编辑弹窗限制在视口内，长内容内部滚动，支持键盘操作、标签关联、错误说明和保存状态。截图：`.runtime/admin-limits-ui/overview-{1440,1024,390}.png`，以及 editor/confirm 同宽文件。
- 本期额度动态读取，剩余时长为 max(0, 上限 - 已用 - 本期预占 - 往期待核对)。修改不清零使用记录或预占，不改变注册日/会员周期/到期日。预占可以在调低后继续结算；尚未获得预占的任务按既有资源和额度检查执行。
- 旧订单保留价格及期限，支付后实际使用当前额度，不因订单旧快照回退套餐配置。后台五项更新与审计原子提交，版本冲突刷新重确认。

## 人工验收

1. 超级管理员打开 `/admin/limits`，检查三档额度与前台定价一致，手机可切换三档。
2. 编辑一档，检查整数限制、单位和当前值；返回修改、取消操作不保存。
3. 核对修改项后再保存；实际修改会立即影响该套餐已有用户，按需要选择目标值。
4. 前台定价及个人中心应在可见时 30 秒内更新，切回页面也立即查询；已有用量与预占不归零。
5. 两个标签页同时编辑，后保存者收到冲突提示；普通管理员能查看但无编辑按钮。

当前仅完成自动化和截图验证，待用户人工验收；没有为演示自动调整业务额度。
