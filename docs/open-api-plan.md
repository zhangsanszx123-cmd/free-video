## 已确认范围

1. 提取字幕/语音原文、时间戳与 SRT，返回标题、平台、时长、source_url、video_url、cover_url。媒体地址可为 null，注明临时地址限制，不提供文件托管。
2. 有效月卡、年卡开放，不新建套餐或改价；免费账号可阅读文档。
3. 共用现有 ASR 时长、单条上限及个人周期，平台字幕免费，查询、导出、复用不扣量；不新增按次收费。
4. 复用现有抖音、B站、YouTube；YouTube 依赖部署网络；不包含小红书、快手新适配。
5. 交付接口、密钥管理、在线文档、Python/Node.js 示例，小程序由接入方通过自身服务端或云函数调用。
6. 参考 AnyToCopy 异步提交与查询流程，使用本站版本化协议及 Bearer 密钥，不要求兼容参考站字段或双请求头。

参考：https://www.anytocopy.com/account/api/docs 。实际参数、错误、限流和示例以 [接入文档](./open-api.md) 为准。

## 源码分析结论

- 原 /api/transcript 同步提取平台字幕，/api/transcriptions 异步转写依赖网站 Cookie 与来源检查；不放宽这些接口作为第三方入口。
- TranscriptionManager 已具备字幕优先、显式 ASR、有界队列、账号 owner、规范 URL 复用；membership 实现 MySQL 额度预占、原周期结算及 30 天历史。
- fun-asr-flash 的供应商账本与用户额度独立，未知提交不能自动重发。本次复用现有能力，不另建收费识别管线。
- 执行队列仍在内存，数据库恢复已保存结果，重启不续跑音轨；平台地址有效期与任务保留期不同。
- downloader.parse 已返回 direct/thumbnail，旧转写未完整保存媒体信息；本次增加 media 持久化和别名目标恢复。

## 方案结构

```text
小程序 → 接入方服务端/云函数（微信身份、任务归属、消费控制、保管密钥）
第三方服务端 ──────────────────────────────────────┘
  → /api/open/v1（密钥、权限、限流、幂等、API 任务授权）
  → 现有 TranscriptionManager / user:<id>
  → 平台字幕 / 明确授权的 ASR
  → 现有历史表、用户额度事务、供应商成本账本
```

- open_api_keys：高熵凭证只存摘要、前缀、名称与时间；密码快照摘要防止旧凭据复活，最多 3 把有效密钥。
- open_api_requests：唯一 (user_id,idempotency_key)、请求摘要、稳定外部 ID、内部 ID、提交状态与到期时间，只授权已登记的 API 任务。
- 用户行锁中完成准入后释放事务，再进入进程提交锁/管理器锁；入队前 on_accept 保存映射。崩溃只核对记录，不盲目重提。
- 到期禁止新任务，允许读取已受理任务；禁用/撤销拒绝后续调用，在途任务继续结算。
- 每账号提交 10 次/分钟、读取合计 60 次/分钟、2 个活动实际提取任务；全站有界队列仍有效，别名按实际目标计算。
- 入口只接受固定平台作品 ID 路径，短链逐跳检查域名、公网 DNS，不开放泛用 URL 下载。适配器后续网络行为仍由部署出站边界约束。
