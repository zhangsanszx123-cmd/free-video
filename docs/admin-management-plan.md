# 管理后台首版方案（已确认）

日期：2026-11-16。

用户需求：新增需要登录的管理后台，目前仅管理注册用户和后台用户。2026-11-16 用户已确认以下推荐范围，实现与自动化验证已完成，待人工验收。最终结果见 [验证记录](./admin-verification.md)，首次初始化与操作见 [后台指南](./admin-setup.md)。

## 1. 推荐首版范围

| 模块 | 推荐功能 | 权限 |
|---|---|---|
| 后台登录 | 独立用户名和密码、退出、修改自己的密码、登录过期提示 | 已创建的后台账号 |
| 注册用户 | 分页列表、按邮箱/昵称/ID 搜索、启停与邮箱验证状态筛选、详情、禁用/启用 | 普通管理员和超级管理员 |
| 后台用户 | 分页列表、搜索、新增账号、修改显示名称和角色、禁用/启用、重置密码 | 超级管理员 |

推荐使用独立后台账号，角色分为超级管理员与普通管理员。后台账号没有公开注册入口，不与前台注册用户互相授权。首版不增加注册用户删除、修改邮箱、代登录、人工验证、手工改会员或额度、订单管理与系统设置页面。

若用户需要注册用户资料修改、重置密码或删除，应先补充确认操作字段和数据保留口径，再纳入实现。

## 2. 页面与布局

- `/admin/login`：独立后台登录页，成功后回到原后台地址，默认进入注册用户列表。
- `/admin/users`：注册用户管理。
- `/admin/staff`：后台账号管理，仅超级管理员可用。
- `/admin` 跳转到注册用户列表；未知后台路径呈现后台 404。

桌面采用左侧两项导航、右侧查询和列表，顶部展示当前后台账号、修改密码和退出。手机使用横向导航和用户卡片，详情集中展示次要字段，避免宽表格撑出屏幕。

注册用户列表展示 ID、邮箱、昵称、邮箱验证状态、账号启停状态、注册时间、当前会员类型和操作入口。详情补充会员到期时间等账号基础信息，不展示密码摘要、会话令牌、邮件凭证或供应商信息。

后台账号列表展示登录名、显示名称、角色、状态和创建时间；登录名创建后不修改。密码只能重新设置，不能查看原密码。

视觉继续使用现有中文系统字体、蓝紫主色按钮，管理区使用浅灰背景、白色内容区和清晰表头。无需新增字体、组件库或状态库；不增加无关统计图、营销横幅和虚构数据。本地样式库的自动营销页结构不适合此后台，布局采用现有项目样式与数据表格通用规则。

## 3. 权限与会话

| 操作 | 游客/前台用户 | 普通管理员 | 超级管理员 |
|---|---|---|---|
| 查询或启停注册用户 | 不允许 | 允许 | 允许 |
| 查看/管理后台账号 | 不允许 | 不允许 | 允许 |
| 修改自己的后台密码、退出 | 不适用 | 允许 | 允许 |

- 后台使用独立 Cookie、会话表、API 请求封装、状态仓库及跨标签通道；前后台可以同时登录，退出和过期互不影响。
- 后端逐接口检查权限。无后台会话返回独立的 `ADMIN_AUTH_REQUIRED`，不能触发前台账号退出；权限不足返回 403。
- 管理员被禁用或密码被重置后，其全部后台会话撤销。角色变动及时重新检查权限，旧页面不能继续执行原权限操作。
- 不允许管理员禁用自己；至少保留一个启用的超级管理员。涉及超级管理员角色或状态的写操作串行检查，避免并发互禁导致无人可登录。
- 写接口保留现有来源检查、密码哈希和限速机制，登录接口不与普通账号共用失败计数键。页面不直接拼接或展示后台内部异常。

## 4. 注册用户禁用的具体含义

推荐定义为：**禁用提交后，不再允许该账号登录或发起需要登录的新请求；已经接受的请求和任务继续按现有规则处理。**

- 禁用独立于邮箱验证状态，保留会员、时长用量、历史和支付订单，不修改注册时间或周期锚点。
- 禁用事务锁定用户、写入状态并删除其全部登录会话；登录创建会话时在同一用户锁内复核状态，覆盖「验密后被禁用」的交错场景。
- 邮箱验证和找回密码不能绕过禁用。推荐禁用时使未使用的邮件凭证失效；重新启用不恢复旧会话或旧链接，也不自动完成邮箱验证。
- 已接受的识别任务继续结算；旧订单迟到付款继续按既定规则记账并开通或标记待退款，保持账号禁用状态。禁用不等于取消任务、退款或撤销会员。
- 禁用账号退出后仍可能按游客规则使用公开下载能力；本功能不封禁 IP，也不增加平台或游客封禁策略。

若用户需要禁用时立即取消已排队/运行任务，需要另行设计任务取消，不能只依靠登录状态实现。

## 5. 初始超级管理员

建议用户名为 `admin`，通过服务器本机初始化命令创建，密码由用户在隐藏输入中设置，不通过聊天、命令行参数或日志收集明文。不设置通用默认密码，不开放网页「首人注册」。

已经存在超级管理员时，重复初始化不能覆盖密码。后台新增账号由超级管理员登录后完成，普通前台用户无法自行升级权限。

## 6. 代码与数据结构

沿用 FastAPI、Vue 和 MySQL，不引入新基础设施。

后端建议新增：

```text
backend/app/admin_store.py    后台账号/会话、用户查询与管理 SQL
backend/app/admin_auth.py     后台认证、权限依赖与初始化命令
backend/app/admin_api.py      /api/admin/* 接口
```

数据库增加后台账号与后台会话表；注册用户表增量增加启停状态及必要时间字段，现有用户默认启用。必要的管理操作保留操作者和时间记录，不保存密码明文。所有迁移沿用 `init_schema()`，不清空现有账号、会员和支付数据。

接口建议：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/admin/auth/login`、`logout` | 后台登录、退出 |
| GET | `/api/admin/auth/me` | 当前后台身份 |
| POST | `/api/admin/auth/password` | 修改自己的密码 |
| GET | `/api/admin/users`、`/users/{id}` | 注册用户列表与详情 |
| PATCH | `/api/admin/users/{id}/status` | 注册用户禁用/启用 |
| GET/POST | `/api/admin/staff` | 后台账号列表、新增 |
| PATCH | `/api/admin/staff/{id}` | 显示名称、角色和状态 |
| POST | `/api/admin/staff/{id}/password` | 重置后台账号密码 |

前端增加独立 `src/admin/` 区域。`App.vue` 根据后台路由使用独立布局，不挂载前台导航、会员浮层和前台登录弹窗；前台身份监听不能重建或跳走后台页面。后台状态复用已验证的请求版本保护思路，避免旧查询或旧 401 干扰新后台会话。

## 7. 分步实施与验证

1. 确认注册用户操作范围与后台账号权限模型。
2. 实现后台账号、登录与权限隔离，提供首位超级管理员初始化方式。
3. 实现注册用户列表/详情和获批操作，再实现后台账号管理。
4. 在独立测试库与端口验证权限、迁移、并发和页面，完成前台回归及构建。
5. 同步需求、设计与验收记录，提供后台地址和人工验收步骤。

重点回归：权限矩阵、前后台登录隔离、被禁用账号所有设备失效、登录与禁用交错、旧邮件链接、超级管理员保护与并发、搜索分页和旧请求保护，以及修改前后会员/订单/历史不受影响。

当前 `:8000` 运行真实 0.50 元支付测试。开发和自动化使用独立测试库、端口及临时目录，关闭测试进程的真实 SMTP、支付和收费模型配置，不与现有业务服务共用清空型测试。功能验证后先核查在途支付，再安排当前服务加载更新并告知用户，避免中断正在操作的真实付款。

## 8. 确认记录

用户已确认首版采用「注册用户列表、搜索、详情、禁用/启用」以及「独立后台账号、超级管理员/普通管理员」两级权限，后台账号操作和禁用语义按本文实施。注册用户资料修改、密码重置、删除等扩展另行确认。
